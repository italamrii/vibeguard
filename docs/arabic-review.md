## Rule `endpoints/cors-wildcard-credentials`

| Key | English | العربية |
| --- | --- | --- |
| `title` | CORS allows any origin together with credentials | إعدادات ⁦CORS⁩ تسمح بأي مصدر مع إرسال بيانات الاعتماد |
| `summary` | With Access-Control-Allow-Credentials: true, browsers send the user's cookies on cross-site requests. If the server also echoes back whatever Origin the request had (cors({ origin: true }), a callback that always allows, or res.setHeader('Access-Control-Allow-Origin', req.headers.origin)), any website the user visits can call your API as them and read the responses. A literal "*" with credentials is rejected by browsers, but it shows the intent, and the usual "fix" is reflection. | عند ضبط ⁦Access-Control-Allow-Credentials: true⁩ يرسل المتصفح ملفات تعريف الارتباط الخاصة بالمستخدم مع الطلبات القادمة من مواقع أخرى. وإن كان الخادم يعيد أيضًا أي قيمة ⁦Origin⁩ جاءت في الطلب (⁦cors({ origin: true })⁩ أو دالة تسمح دائمًا أو ⁦res.setHeader('Access-Control-Allow-Origin', req.headers.origin)⁩)، فإن أي موقع يزوره المستخدم يستطيع استدعاء واجهتك باسمه وقراءة الاستجابات. أما "*" الحرفية مع بيانات الاعتماد فيرفضها المتصفح، لكنها تكشف النية، و"الحلّ" المعتاد لها هو إعادة الـ ⁦Origin⁩ كما هو. |
| `remediation` | Allow an explicit list of trusted origins. Only set credentials: true when cookies must cross origins. Never echo the request Origin without checking it against the list. | اسمح بقائمة صريحة من المصادر الموثوقة. ولا تضبط ⁦credentials: true⁩ إلا إذا كان لا بد من إرسال ملفات تعريف الارتباط بين مصادر مختلفة. ولا تُعد قيمة ⁦Origin⁩ الواردة في الطلب دون مقارنتها بالقائمة. |
| `message.permissiveOnCookieRoute` | CORS allows any origin on code that relies on cookies for authentication. Without credentials: true browsers will not send the cookies, so this is not directly exploitable, but it is one config change away. Restrict the origin list. | إعدادات ⁦CORS⁩ تسمح بأي مصدر في شيفرة تعتمد على ملفات تعريف الارتباط للتحقق من الهوية. وبدون ⁦credentials: true⁩ لن يرسل المتصفح تلك الملفات، لذا لا يمكن استغلال ذلك مباشرة، لكن تغييرًا واحدًا في الإعدادات يكفي لجعله ثغرة. قيّد قائمة المصادر. |
| `message.reflectedOrigin` | CORS echoes any request origin and allows credentials: any website can make authenticated requests as your users and read the responses. | إعدادات ⁦CORS⁩ تعيد أي مصدر وارد في الطلب وتسمح ببيانات الاعتماد: يستطيع أي موقع إرسال طلبات موثّقة باسم مستخدميك وقراءة الاستجابات. |
| `message.wildcardWithCredentials` | CORS combines Access-Control-Allow-Origin "*" with credentials. Browsers reject this combination, so cross-origin calls fail. Use an explicit origin list, not reflection. | إعدادات ⁦CORS⁩ تجمع بين ⁦Access-Control-Allow-Origin "*"⁩ وبيانات الاعتماد. يرفض المتصفح هذا الجمع فتفشل الطلبات بين المصادر. استخدم قائمة مصادر صريحة، لا إعادة الـ ⁦Origin⁩ كما هو. |

## Rule `endpoints/auth-route-no-rate-limit`

| Key | English | العربية |

| `title` | Login / signup / reset endpoint without rate limiting | نقطة تسجيل دخول أو تسجيل حساب أو استعادة كلمة مرور دون تحديد للمعدّل |
| `summary` | Custom credential endpoints (login, signup, password reset, OTP verification) are public by necessity. | `message.noRateLimit` | {endpoint} handles credentials and has no rate limiting in code. ## Rule `endpoints/webhook-without-signature`

| Key | English | العربية |
| --- | --- | --- |
| `title` | Webhook endpoint does not verify the sender | نقطة ⁦webhook⁩ لا تتحقق من هوية المُرسِل |
| `summary` | Webhook URLs are public and easy to guess (/api/webhooks/stripe).
